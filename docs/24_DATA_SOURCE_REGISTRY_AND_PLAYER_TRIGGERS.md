# 数据源清单与玩家触发更新

本规范补充文档 21/22/23。玩家决定游戏时间与进程；每次数据更新均由玩家主动触发。脚本不按现实月份推断游戏月份，不因重启自行推进游戏或批量覆盖历史。采集、校验、计算、导出和同步阶段均不调用模型。

新开模型对话时先读 [27_DATA_WINDOW_RUNBOOK.md](27_DATA_WINDOW_RUNBOOK.md)。数据任务在交付后停止；GM 决策由玩家另行找到对应模型触发，游戏执行也由玩家批准具体方案后单独触发。采集入口不生成交易/战术候选。确定性财务差额、计数和变化比较属于数据处理，不代表开始 GM 决策。

## 重启与已保存数据

重启影响进程句柄、PID 和部分运行时地址。已入库历史快照不依赖这些地址。下次采集会打开当前进程，PID/模块变化则废弃旧堆地址并扫描，缓存失效也扫描；不需要每次重启通知模型。旧版本的实际新 PID 恢复证据见文档 23；当前目录校准版本已通过同 PID 强制缓存失效验证，实际新进程验证仍待下次游戏重启，见文档 31。

数据库不会因为游戏重启自动刷新。玩家触发更新时才重新观测并计算差异。若上一次游戏修改未存盘，重新加载后的真实游戏状态可能回退；新快照如实记录，不能伪装成同一条连续成长。换存档、新开局或读旧档必须明确 career_id 和新的检查点/历史分支；当前还没有可靠的内存存档唯一 ID 自动识别。

员工池在赛季开始完整更新是合理节点，但季中也会发生人员变动。统一采集每次按目录刷新员工池；员工槽号不是跨存档永久身份。最近批次数量仅描述对应采集时刻，不能作为以后固定遍历上限。扩展来源详见文档 31。

## 统一更新任务

当前实现为 `full_verified_v1`：每个事件都刷新全部已验证来源，以保持批次完整和审计一致。它尚未实施按来源跳读/缓存。此实现通常几秒，地址失效扫描约数秒；不能将“推荐频率”误写成已实现的独立增量采集器。

入口为 `scripts/run_data_update.ps1`：玩家指定 career_id、游戏日期、赛季、框架月序号、事件和快照名。单任务互斥锁防止多个窗口同时入库/发布。游戏日期由玩家提供，并编码进 SQLite 快照 notes，纳入审计摘要；它不是声称从游戏内存自动读取的日期。

```powershell
# 当前局 2021-11-20 日终检查点，非月末
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_data_update.ps1 -SaveId mc_haliburton_2021 -GameDate 2021-11-20 -Season 2022 -Month 1 -Event checkpoint -Name NOV20_CHECKPOINT -GamesOnDateComplete -Publish -NewWindow
```

`-NewWindow` 启动单独的 PowerShell 数据任务窗口，不创建模型对话。`-Publish` 才执行配置仓库的 GitHub 同步；玩家已授权公开仓库及本次数据库/JSON 发布。省略时只生成本地审计数据库与阅读包。UAC 提权仍是正常的 Windows 权限步骤。窗口任务不包含任何游戏写入入口。

每个月由玩家在真实游戏月末触发 `monthly_close`；赛季开始触发 `season_start`；其他支持事件为 `checkpoint`、`post_transaction`、`staff_change`、`roster_import`、`draft_pre`、`draft_post`。当前工资规则只配置了 2021-2022，不能用 2022 的工资规则给后续赛季签发凭证。

框架 `Month=1` 沿用现有 M01 标签，当前代表这一局的 11 月采集段；游戏日期另存精确 ISO 日期。11 月 20 日完成比赛不等于 11 月已经闭账。每次应使用能够区分检查点的 Name，避免误覆盖不同游戏日期的同名快照。

## 执行顺序与失败处理

玩家触发 → 当前进程只读校准 → 全部已验证来源采集 → SQLite 入库/清单 → 内存抽样审计 → Python 确定性计算/差异 → 自动导出 JSON/数据库归档 → 按要求上传 GitHub → 记录数据更新时间与上传成功时间 → 回执。按文档 29 简化同步，不运行额外 JSON 检查或下载比较。

任一步失败即停止后续步骤，不能给失败批次签发合格数据。GitHub 同步失败时保留本地已审计数据，不重启游戏、不重新模拟比赛、不伪造远端成功。失败的远端发布可以针对同一有效导出重试。

数值计算均由 Python/SQLite 完成，模型获取明确的计算输入、方法、版本与结果。逐场数据尚不存在时，不能从工资、POE、上一月或现实 NBA 数据填补胜负/效率。
