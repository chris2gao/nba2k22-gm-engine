# 数据源扩充：当前实现与未解字段

## 工作边界

本次由玩家触发，只读取 NBA2K22 内存，更新数据库、自动导出并同步私有 GitHub。未修改游戏，未运行正式 GM 回合。CT、NBA2K22 Tools 的结构定义和梦幻星辰只作为定位参考；未执行 CT 注入或修改器写入。

玩家后续确认游戏已从 2021-11-20 推进数日，并授权直接使用当前数据。因此新批次使用 `game_date=null`、`game_date_provenance=PLAYER_AUTHORIZED_CURRENT_DATE_UNKNOWN`。不能继续标注为 11 月 20 日，也不能使用电脑日期计算球员年龄。拿到准确游戏日期后，常规更新会按生日重新计算年龄。

## 已接入自动采集的来源

| 来源 | 定位与数据类型 | 当前结果及限制 |
| --- | --- | --- |
| 名单目录 | 由 Jordan / Olajuwon 双锚点校准的旧球员池原点实际包含目录；每项为数量与 uint64 指针 | 每次读取指针和数量，并验证下一数组边界，不保存绝对地址作为永久身份 |
| 全局球员 | 目录 `+0x20` 指针、`+0x18` 数量；步长 `0x4F0` | 本次 3,391 个球员槽位；保留旧原点槽号，加目录槽位共遍历 3,392 个位置，得到 3,383 个姓名有效模型。旧固定 3,320 的上限取消 |
| 球队赛季统计 | 目录 `+0x1D0` 指针，数量 `+0x1C8`，步长 **62 字节**；球队 `+0xE80` uint16 索引 | W `+5` uint8，L `+0x3C` uint8；当前赛季头部码 122 即 2022。30 队战绩、得失分、投篮篮板助攻等累计量已采集 |
| 球员赛季统计 | 目录 `+0x190` 指针，数量 `+0x188`，步长 **48 字节**；球员 `+0xFC` uint16 索引 | 本次 389 人具有当前赛季统计；`65535` 表示无可用统计索引，保持 NULL，不能自动当作零场 |
| 出生日期 | 球员 `+0x6E` 低 12 位年、`+0x6F` 高 4 位月、`+0x70` 低 5 位日 | 无效日期为 NULL。`+0x70` 高 3 位仍用于历史新秀分类，两者互不覆盖 |
| 完整能力项 | 球员 `+0x41F..+0x456` 中定义的 **55 项**，其中包含身体部位耐久和潜力 | 每项同时保留 raw 和按现有 `config.raw_to_rating` 规则解码的值；潜力来自 `+0x441`，废止旧 `+0xEB` 的猜测 |
| 球员合同 | 六年金额 `+0x1A4..+0x1B8`，每项 **31 位**；合同年数、类型、选项、禁止交易等位域 | 高位标志不再被读为数十亿美元薪资；金额不等于已保障金额。完整 CBA 账本仍不齐全 |
| 员工池 | 目录 `+0x140` 指针，数量 `+0x138`，步长 `0x160` | 本次 1,470 槽，1,458 个有姓名。旧校准锚点是姓名地址；实际记录原点在姓名前 `0x30`。遇到空姓名不再结束池遍历 |
| 员工归属 | 员工 `+0x18` uint64 球队指针，职位 `+0x10E` 起始 bit2、3位；与球队职位指针反向核对 | 30 队各 8 个角色，共 240 个在职关联；非 NBA/未匹配指针保留未映射，不自行认定自由员工 |

球队的员工角色指针：主教练 `0xCE8`，助教 `0xCF0`，首席球探 `0xCF8`，训练师 `0xD00`，GM `0xD08`，老板 `0xD10`，CFO `0xD18`，副 GM `0xD20`。

员工攻防等等级是半字节代码，不是 25–99 球员能力。导出保留代码，不能把它们当作同一量表。员工薪资与剩余年数按结构位域读取。

## 数据结构与自动流程

`config/memory_field_profile.json` 保存字段偏移、长度、位移和已知枚举；`src/source_extensions.py` 为确定性解码。主采集脚本每次自动刷新以下新增表：

- `player_source_details`：本批次球队、阵容槽、模型槽、姓名/face ID、生日/年龄、55 项能力、合同字段、赛季统计及原始球员结构。
- `staff_source_details`：完整员工目录槽位、身份、角色、球队关联、字段与原始记录。
- `team_source_stats`：当前索引、累计统计、原始统计记录。
- `draft_asset_observations`：选秀资产候选原始记录，未确认的年、轮次、保护保持 NULL。

这些是新增的快照表，不回填旧批次。旧快照没有扩展记录时继续表示当时的采集范围。全局球员池表新增 `source_details_json`；每次从当前完整目录重新采集。老槽号用于兼容历史选秀机制，但它仍不是跨名单、跨存档的永久人物 ID。

网页导出自动在球队阵容内加入生日、年龄、55 项能力、六年薪资及详细来源，并输出 `season_totals.json`、`staff.json` 和候选 `draft_assets.json`。SQLite 归档仍随私有 Release 上传；更新状态仍只用 `data_updated_at` 与 `uploaded_at`。不恢复 JSON 哈希、逐字段导出核验或下载比对。

场均和命中率由 Python 从累计量计算，命中率使用 0–1 比例；零分母为 NULL。赛季累计数据不能称为月度或逐场统计。排名需要完整的并列处理规则，暂不使用简单排序冒充游戏排名。

## 实机来源核对

玩家提供湖人 15–5、国王 14–5、勇士 9–9；内存表三队完全对应。全联盟胜负合计分别为 **279 / 279**，得失分合计分别为 **65,021 / 65,021**；30 队与 389 个当前球员统计的得分都满足 `2*FGM + 3PM + FTM`。

采集审计重新校准，核对球队统计、球员扩展结构/解码、员工结构/双向关联和目录覆盖。此处是来源与数据库核对，不是网页 JSON 同步检查。玩家推进比赛、切换存档或修改数据后，应重新采集，旧审计不能证明新状态。

强制废弃地址缓存的验证发现：进程中有多份能匹配 Jordan / Olajuwon 姓名的名单副本。现已增加目录布局和数组边界验证，从同一目录派生球队与员工地址；不再让三项扫描各自选中不同副本。修复后强制失效缓存重新扫描成功，3,383 个有效球员结构与数据库全部吻合，差异 0。该验证在同一 PID 内模拟缓存失效，**不等同于实际关闭重开游戏后的新 PID 验收**；后者在玩家下次重启后执行正常采集即可确认。

## 仍待解决的具体缺口

### OVR 总评

NBA2K22 Tools 的 55 项能力定义没有直接给出总评字段。玩家确认 MC 哈利伯顿界面锁定 60、库里 96；两人的原始球员结构中未找到符合这两个样本的直接字节或既有能力编码字段。因此 `overall_rating` 继续 NULL，不能用能力均值、潜力或真人 NBA 数值填充。

下一步需要游戏球员卡中总评的运行时缓存地址或对应 CE 项。MC 显示锁定总评与实际能力应分开表达；若找到缓存，要验证普通球员切换和 MC 特例后才能接入通用采集。

### 选秀权

目录 `+0x2B0`、数量 `+0x2A8`，步长 32，包含 504 个槽位。头两个 uint64 指针可以映射到当前球队和原球队候选，第三个指针部分关联已选中的球员，尾部是未完全解码的元数据。

局部解码观察到 2022–2026 年每年两轮、每轮 30 条，以及 2021 年已选记录和未定年记录。与能映射到全局模型的 2021 年新秀交叉比对，年轮候选吻合；但尚无玩家当前界面或同版本权属/保护字段的独立样本，**不将这些候选作为可交易的已认证资产**，不把未定年编码当作 2000 年选秀权，也不推断无保护。玩家当前 MC 无法查看选秀权，不要求其切换存档或改模式。

下一步需要带年份/轮次/归属/保护条件的同一存档界面或 CE 数据项。当前原始记录已随快照保留，后续可以按证据扩展，不需重新猜造历史状态。

### 合同完整账本与其他字段

六年薪资、球员/球队选项和基础合同条款已获取；逐年保障金额、死钱明细、例外、占位、完整交易限制和自由球员权利尚未齐全。`full_cba_ledger_verified=false`，不签发合法交易结论。逐场赛果、月度分段、伤病、完整轮换与支出明细继续按实际缺口标记。

## 新窗口更新

有准确日期时继续用文档 27 的常规命令。只有玩家明确授权使用当前状态且日期未知时：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run_data_update.ps1 -SaveId mc_haliburton_2021 -GameDateUnknown -Season 2022 -Month 1 -Event checkpoint -Name CURRENT_CHECKPOINT -Publish
```

`-GameDateUnknown` 与 `-GameDate` 互斥；未知日期不能声明当日比赛已结束，也不能计算准确年龄。数据完成后停止，GM 与游戏执行继续由玩家分别触发。
