- **Web GPT only:** use `web_gm/baselines/README.md` and `docs/35_WEB_GPT_BASELINES_AND_MEMORY_PROTOCOL.md`. Three role-specific baseline prompts under `web_gm/baselines/`: GM (basketball strategy and proposals), DEVELOPMENT (requirements, Codex implementation specifications and independent acceptance), ANALYTICS (read GitHub published batches, run safe deterministic Python/SQL analysis, commit analysis-only Markdown/JSON to `docs/gm_analysis/`). The role's rolling index is `web_gm/memory/{GM,DEVELOPMENT,ANALYTICS}_CURRENT.md`; each task writes a new session summary when authorized. New chat windows re-read GitHub docs; no automatic cross-chat memory or model dispatch.
- **GM season-chat lifecycle (player-confirmed 2026-10-17):** open **one derived Web GPT GM decision chat per in-game season**, not one chat per GM decision or month. Monthly, trade-deadline, playoff, offseason and event decision nodes are individually player-triggered within the same season chat. Each node can contain up to 3 GM deliberation rounds; that limit does not close the season chat. Persist each node to the existing `web_gm/seasons/<season_id>/windows/Wxx_...` archive and update the season INDEX and GM_CURRENT. Existing Wxx names are archive node IDs, not mandatory separate chats. The season chat ends only after player-confirmed season close and archival; next season uses a new GM chat. This does not authorize automatic GM triggers, game writes, or Codex work. DEVELOPMENT and ANALYTICS chat lifecycles remain task-scoped.

Routine basketball analysis reports and their GitHub synchronization belong to the Web GPT ANALYTICS role, not a mandatory Codex relay.
