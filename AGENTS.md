# NBA2K22 GM project instructions

- GM v1 offline development uses src/gm_core and scripts/gm_prepare.py, gm_calculate.py, gm_validate_proposal.py. Read docs/30_GM_V1_DEVELOPMENT_AND_ACCEPTANCE.md and web_gm/GM_DECISION_SOP.md. Never import game-memory/write modules into gm_core, run a formal GM round during development, approve proposals from model-provided fields, alter formal team dossiers, or change the accepted timestamp synchronization pipeline. gm_policy.json is a proposed operating configuration awaiting player confirmation. Development simulations go under _exports; no automatic capture, model dispatch, publication, or execution.

- GitHub synchronization uses timestamps only at the player's request: data_updated_at and uploaded_at in latest.json. Do not run JSON hash/field checks, verify_web_export.py, test_web_export_guards.py, or download-and-compare checks during routine export/publication. Source memory calibration and capture auditing remain in place. Read docs/29_SIMPLE_DATABASE_SYNC.md for the current sync contract; it supersedes older hash-based JSON handoff instructions.

- Data initialization/update, GM decisions, and game execution are three separate player-triggered tasks. Never start a later stage because an earlier stage finished. Data jobs end after the requested capture/audit/calculation/publication; they must not call generate_gm_proposals. New data windows read docs/27_DATA_WINDOW_RUNBOOK.md; approved execution windows read docs/28_EXECUTION_WINDOW_RUNBOOK.md.

- Read docs/22_DATA_SOURCE_AND_DECISION_GOVERNANCE.md for truth/approval rules; docs/24_DATA_SOURCE_REGISTRY_AND_PLAYER_TRIGGERS.md for data jobs; docs/25_GITHUB_AND_WEB_GM_PROTOCOL.md for web handoff. Avoid loading every historical design document for a data update.
- Read docs/26_GAMEPLAY_ROLES_AND_WORLDLINE_RULES.md and config/gameplay_policy.json for current player rules: sequential 1984-2020 draft cycles; game-controlled natural development; no ordinary player edits; specifically approved historical gravity only; MC growth story deferred. Legacy automatic awakening/growth rules are superseded. Web access testing belongs to the player.
- The player alone triggers data updates and supplies the game date and career ID. Game dates are player-confirmed context, not currently observed memory fields. No calendar scheduling or autonomous gameplay progression.
- Use scripts/run_data_update.ps1 for a player-triggered update. The scripts perform calibration, capture, audit, computation, export and optional publication to the configured GitHub repository without a model. Use a separate terminal with -NewWindow when requested.
- Historical SQLite snapshots remain facts at their capture time; process pointers are runtime-only. Recalibrate each collection, fail closed on unreadable/invalid data, and never invent missing game statistics.
- Any numeric reasoning must use Python/SQL or an existing deterministic result. A schema column does not establish that its value is observed.
- Actual game writes, execution of trades, and changes to formal team decision documents or decision execution scripts require player approval of the concrete proposal. Read-only capture, audits, data exporter maintenance and a requested data sync are separate from game decision execution.
- Never stage live database files, runtime maps, local logs, backups or credentials. Audited derived JSON is versioned under published/; SQLite archives are Release assets. The player explicitly authorized the public repository and publication of this game database and JSON on 2026-10-17; config/github_sync.json records the configured visibility. Preserve exact published file bytes.
- The data-only publisher must not commit unrelated staged changes, force push or publish a source-code revision it did not review. No credential files or secrets may be read or committed.
- Web decisions cite career, batch and commit. Worldline fiction and real NBA references never overwrite observed game facts. Remote decision intake/execution is not implemented; never treat a remote approved=true field as human approval.
